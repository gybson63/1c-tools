# Руководство: cfe-into-cf

## Назначение

Утилита переносит **всё** содержимое указанного расширения в основную конфигурацию информационной базы:

- собственные объекты расширения (Own) — добавляются в основную CF;
- изменения заимствованных объектов (реквизиты, формы, макеты);
- BSL с `&ИзменениеИКонтроль` / `#Вставка` / `#Удаление` — применяется к модулям основной CF.

Расширение после переноса **не удаляется и не отключается** — это отдельный шаг администратора.

## Пайплайн

1. `DumpConfigToFiles` — выгрузка расширения и основной CF (hierarchical).
2. Инвентаризация Own / Adopted / BSL.
3. **Алерт новых объектов** — без `--accept-new-objects` (или подтверждения в GUI) процесс останавливается с кодом 2.
4. При заданных параметрах хранилища — `ConfigurationRepositoryLock` по списку объектов (+ корень `Configuration`, если есть Own).
5. Слияние XML/BSL во временную копию выгрузки основной CF.
6. `LoadConfigFromFiles` (частичная загрузка по списку файлов).
7. `UpdateDBCfg` (если не указан `--skip-update-db`).
8. Опционально `--repo-commit` — помещение в хранилище (по умолчанию выключено).

## Почему не `/MergeCfg`

Пакетный merge файла `.cfe` плохо учитывает семантику расширения (`ObjectBelonging`, директивы изменения и контроля). Контролируемый разбор выгрузки даёт полный отчёт и предсказуемый алерт по новым объектам.

## Хранилище

Параметры:

- `--repo-path` / `--repo-user` / `--repo-password`

Формируется Object list XML (`http://v8.1c.ru/8.3/config/objects`) и вызывается `/ConfigurationRepositoryLock -Objects … -revised` для **основного** хранилища (без `-Extension`).

Если параметры хранилища не заданы, захват пропускается с предупреждением. Если конфигурация реально на хранилище — укажите параметры, иначе загрузка может завершиться ошибкой Конфигуратора.

## Риски при новых объектах

Добавление Own-объектов меняет дерево метаданных и часто структуру БД. Проверьте:

- права и роли;
- планы обмена / РИБ;
- префиксы имён и пересечения с типовой конфигурацией;
- необходимость последующего отключения расширения.

## Offline-режим

`--skip-designer` + `--extension-dump` + `--main-dump` позволяют отладить merge без ИБ. Результат — каталог `main-merged` в `--work-dir`.
